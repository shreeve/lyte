## 0. Decisions for the owner — answer these before the wave rolls

Tomorrow's session starts here. Each has a recommendation; none is made
unilaterally.

1. **File-transfer consent UX (privacy-sensitive — the big one).** Files
   are heavier trust than clipboard: a remote peer writes to your disk.
   Choices: per-transfer prompt vs a standing per-host "accept files"
   toggle (visible in-session, like the clipboard toggle LYTE-PLAN §8
   already mandates); where dropped files land (a dedicated
   `~/Downloads/Lyte/` style directory vs the desktop); and v1
   directionality. **Recommendation:** standing per-host toggle + an
   always-visible in-session indicator, dedicated drop directory, v1 is
   client→host drop only (the CL-16 gesture); host→client waits for H5's
   drag-out story, which is a genuinely harder windowing problem.
2. **Clipboard v2 (images/rich types) — H3 stretch or H4?** The consent
   tiers (`Off / Text only / Text + images`) are already designed
   (LYTE-PLAN §8), and an image blob is bulk-channel cargo, not CTRL
   cargo — so v2 becomes cheap once F-2 exists. **Recommendation:** H3
   stretch slice, taken only if the wave runs ahead; otherwise first rung
   of H4.
3. **WASM/browser viewer — H3 or later?** LyteWire's sans-IO,
   no-Foundation discipline is lint-enforced precisely so this stays
   cheap, and the bridge doc (20260720-184200, as amended) already
   reduced the infrastructure to a dumb WebTransport↔UDP datagram relay.
   But a minimal viewer is still: a WASM build target + CI leg, JS shims
   for socket/clock/randomness, WebCodecs HEVC decode, and relay hosting
   — an infrastructure decision (who runs the relay?) the product has
   deliberately not taken. **Recommendation:** not H3. Keep the promise
   warm at zero cost (the lint IS the work); revisit at H4/H5 with a
   one-session spike (does LyteWire compile to wasm32 today?) as the
   scout. The relay-hosting question rides with it.
4. **Non-LAN reach — does the hotel pain change the doctrine?** Tonight's
   move is evidence: a traveling host means a changed address, possible
   client isolation, no LAN discovery. The doctrine (decision record §6,
   LYTE-PLAN §7) says v1 remote reach is Tailscale or a port-forward, no
   rendezvous service, no relay fleet — and the protocol already keeps a
   relay-shaped hole open without surgery. **Recommendation:** doctrine
   holds for H3. The actual pain tonight is *session survival across
   address change and re-dial ergonomics*, which F-5 attacks directly;
   Tailscale remains the honest answer for reachability. Rendezvous/NAT
   traversal is an H5/H6 discussion with its own infrastructure bill.
5. **The wire-version batch (D-5).** Three parked items now want the same
   discussion: the typed fold-in of capability key 9 (deliberately left
   on the forward-compat spine at the codec promotion — moving it into
   the typed set means a capabilities vector-file version), clipboard
   v1's capability key (riding the same spine as it lands), and HS-16's
   parked wire wants (an RFC 8888-style ECN/marking field, a
   receive-window hint). **Recommendation:** hold ONE doc-only
   wire-minor-version discussion during H3 (one session, no bytes
   shipped); bump only when a feature actually needs new spine fields.
   Frozen vectors never regenerate — additions append, semantics changes
   version; that policy is why this can wait without rotting.
6. **Printing stays H5 — confirm.** It wants the bulk channel (F-2) and a
   host IPP leaf, neither H3-critical; the PDF-pivot sketch (host plan
   §6) stands. **Recommendation:** confirm H5.
7. **Multi-monitor selection + dynamic resolution/scale — H4, confirm.**
   Both are session-parameter work the overview already specified
   (renegotiation via typed CTRL + clean IDR restart; chroma/codec stay
   connect-time). Multi-monitor adds capture-side portal stream
   selection; resolution change adds an encoder reconfigure — both pair
   naturally with H4's HS-19-era encoder/policy work and neither blocks a
   feature-channel wave. **Recommendation:** confirm H4, alongside 4:4:4,
   cursor-rendering options, and HDR (HDR honestly last — Wayland HDR
   capture and NVENC plumbing are both young).

Also queued for the human, not decisions: the human-at-glass legs (CL-8's
Keychain zero-UI dial from a real GUI session; CL-13's strip-feel leg l)
and the CP-1-style call on when the damage-vs-wake policy revisit gets its

  HS-18 legs a–g, CL-13 legs h–l, codec-promotion legs m–n, the
  repair-answer-books leg p — all blocked on pup's return. The leg lists
  live in their wave entries; this plan references them, it does not
  restate them. Two hard facts: the HS-18 C leaf is **uncompiled
  anywhere** (Linux-only — the pup build runs FIRST), and the last
  green-on-both-platforms state is the H2-exit 372/104/104, so everything
  since (Wire 388, Host 110, root 116 on Mac) is Mac-attested only.
  Clipboard v1's own live legs join this queue the moment it lands.
- **The Linux clipboard OS leaf.** Clipboard v1 lands against a *mocked*
  host seam by design. The real leaf — the portal Clipboard API attached
  to the RemoteDesktop session we already hold for input (host plan §6:
  selection-change signals + fd-based transfer both directions;
  `wl-clipboard` is NOT a fallback on GNOME; a Shell extension is the
  last resort) — is F-1, the first feature rung.
- **Capability key 9 typed fold-in** — parked at the codec promotion as a
  wire-version discussion; folded into D-5 (owner decision 5).
- **Encoder VBV consuming frameByteCeiling** — the one debt item the H2
  gate itself named as a live dynamic: run B2's post-release tail cycled
  500→~900 kbps under sustained synthetic damage because ceiling-sized
  frames pour into a floor-squeezed pacer (the number is computed,
  logged, and test-pinned — 59,937 B @ 20 Mbps/60 fps — but no NVENC
  reconfigure consumes it). D-1.
- **Repair-lane DSCP** — CL-12's live leg: 54 repair datagrams sent, 17
  accepted; under a floor squeeze the videoTail queue is where repairs
  die. A tail-class marking is a wire-policy call (per-packet cmsg, zero
  protocol bytes). D-2.
- **HandshakeGate cookie-mode enforcement** — W8 landed and the client
  answer path is armed in every dial, but the host never escalates, so no
  live dial has ever drawn a 0x13. D-3.
- **M7 audio remainder** — WSOLA accelerate + skew term + device-change
  handling. Evidence: CL-11's honest trade — silence-free playout bought
  with 90–120 ms of adaptive jitter target on clumpy Wi-Fi (pipe p50/p99
  ~98–102/127 ms); accelerate lowers the equilibrium. D-4.
- **Half-open ends found, assigned not orphaned:** reconnect/takeover UX
  (client seam named at CL-7, host session-busy story never existed —
  folds into F-5); Work/Play presentation scheduling and the 4:4:4
  fixtures (old wave-4 CL-12/CL-13 rows, untouched per the H2 gate — H4
  territory with HS-19 behind CP-1); the damage-vs-wake revisit (owed
  data, collect during D-0/D-1 live runs); `lyte sniff` payload
  decryption behind a debug key-export flag (H3+ sketch in the master
  plan — unscheduled, cheap, take opportunistically).

## 2. The candidates, weighed

The ordering test: (a) does it widen the gap COMPARISON names (clipboard,
file transfer, printing — the impossible-with-Sunshine features), (b) does
measured reality demand it (tonight's hotel move; the gate docs' named
dynamics), (c) does it fit one worker-session at H2 calibration, (d) does
it respect the ladder (LYTE-PLAN §6: H3 features, H4 quality/policy, H5
conveniences)?

**In, ordered:**

1. **Clipboard completion** (F-1 + its joint gate) — clipboard v1 is
   landing now; a mocked seam is not a feature. Finishing it first makes
   H3's opening move the first thing Sunshine could never do.
2. **Drag-and-drop file transfer** (F-2/F-3/F-4) — COMPARISON's next big
   one. The transport pillar already rules the shape (feature channels
   are independent reliable lanes "so a file transfer never blocks a
   clipboard paste"); what does NOT exist is a bulk mechanism: the ARQ
   sublayer's scope is deliberately tiny (control, sparse idle frames,
   feature messages) and a multi-MB payload on the ordered CTRL stream
   would head-of-line-block input behind file bytes. So the wave's long
   pole is F-2 — the chunked, resumable, backpressured bulk channel in
   LyteWire — and both ends' file halves code against its frozen vectors
   (master plan ruling 12: vectors are the contract).
3. **Session roaming/reconnect hardening** (F-5) — evidence-driven:
   tonight's hotel move means a changed host address and possible client
   isolation; the standing reconnect/takeover seam has no host
   session-busy story. The mechanism exists (HS-12's gate: rebind
   mid-stream → resume ≤400 ms); what's missing is policy and UX on both
   ends. Cheap relative to its daily-life payoff.
4. **Clipboard v2 (images)** — stretch, owner decision 2. After F-2 by
   construction (an image is bulk cargo).

**Out, with reasons:**

- **Printing** — H5 (owner decision 6): wants F-2 plus an IPP leaf;
  nothing about it sharpens H3's exit.
- **Multi-monitor, dynamic resolution/scale** — H4 (owner decision 7):
  session-parameter machinery is specified, the work is capture/encoder
  territory that belongs beside HS-19 and the policy integration.
- **WASM/browser viewer** — not H3 (owner decision 3): infrastructure
  decision + multi-slice surface; the lint keeps it cheap later.
- **Rendezvous/NAT traversal** — doctrine holds (owner decision 4);
  Tailscale is the v1 remote answer, F-5 addresses the real pain.
- **Video niceties** (cursor rendering options, HDR, 4:4:4) — H4. 4:4:4
  is already H4's headline (LYTE-PLAN §6); cursor metadata is a feature
  channel that can ride any later wave; HDR is honestly furthest out.
- **Audio niceties** (surround, mic passthrough) — H5+. The mic-back
  channel was explicitly "a future message type, not v1" (LYTE-PLAN §4);
  surround is a capability-negotiation item with no demand signal yet.
  D-4 (the M7 remainder) is the audio work that has measured evidence
  behind it, and it IS in the wave.

## 4. Wave structure — who runs where, what serializes

One coherent worker per package territory, never two in one package; long
live runs look stalled from transcripts — don't kill the quiet.

- **Wave 0 (tonight/tomorrow, partially parallel).** D-0 is the pup
  catch-up worker — it owns Host/ and root LIVE surfaces but edits no
  code, so the **Wire/ worker starts F-2 concurrently** (Mac-local,
  different territory). Nothing else runs live until D-0 clears; if the
  hotel network refuses peer-to-peer (client isolation), Tailscale or a
  hotspot is the honest workaround and gets recorded, not hidden.
- **Wave 1 (three territories, three workers).** Host/: F-1. root: D-4.
  Wire/: F-2 continues (it is the long pole; everything file-shaped
  waits on its vectors, nobody waits idle — that's what the debt rungs
  are for). J-G3a lands the moment F-1 is green — the clipboard gate is
  deliberately early: the first Sunshine-impossible feature should not
  wait for the file work.
- **Wave 2 (parallel again).** Host/: F-3, then D-1 → D-2 → D-3 (D-2 and
  D-3 can share D-1's live session window). root: F-4 against F-2's
  frozen vectors — the two file halves meet live only at their joint
  legs, the CL-1-against-published-vectors pattern.
- **Wave 3 (serializes).** F-5 touches root AND Host/ — one worker, both
  territories, by exception and declared. D-5 is a docs session with the
  owner. F-6 only if the owner ruled it in and the wave is ahead.
- **Wave 4.** The H3 joint gate, one verification worker, no feature
  code touched — the H1/H2 gate discipline exactly.

Deferred-leg discipline, restated once: any slice whose live leg pup's
availability blocks lands Mac-side with its legs enumerated
DEFERRED-PENDING-HOST in its HANDOFF entry — enumerated, ported, and run
before J-G3. J-G3 does not pass over a non-empty deferred ledger.

## 5. J-G3 — the H3 exit, spelled out once

**H3 exits when one coherent live session proves the feature channel is
real, and the ledger is empty.** Specifically, in one run (plus adversity
legs in the H2-gate shape), both ends at committed HEAD, host built from
git archive:

- Text clipboard both directions through the in-session toggle, loop
  prevention observed on the wire (origin suppression + content-hash
  dedupe), ceiling enforced.
- A ≥100 MB file dragged onto the stream window lands on the host
  sha-identical — through a video-scoped loss leg AND a mid-transfer
  blackout with resume — while video stays `.rendering` and the audio
  NIC cadence p99 holds within 5±2 ms (H2's measured bar: p50 4.999 /
  p99 5.978 ms — bulk transfer may not degrade it).
- A mid-session network change resumes the session without re-pairing;
  the two-client takeover answer is typed and clean.
- H2's hygiene bar re-held: 0 unseal failures both ends' books, ARQ
  exactly-once, clean typed teardown, secrets shas byte-identical,
  netem/iptables removed and verified after.
- The deferred-pending-host ledger is EMPTY (D-0 legs + every H3 slice's
  deferred legs), and D-1…D-4's gates are green — J-G3 certifies the
  debt paid, not just the features lit. D-5 is a decision, it gates
  nothing.

Then COMPARISON.md's measured column gets its update (the doc's own
standing instruction), and H4 — 4:4:4, policy, resolution, the encoder
work behind CP-1's successor call — starts from a clean sheet.

## 6. Risks, honestly

| Risk | Mitigation |
|---|---|
| **Portal Clipboard API surprises** (F-1) — the RemoteDesktop portal has burned us before (CP-5: hostile headless consent); the Clipboard extension may carry its own consent/token quirks on a headless session | Same playbook that worked: spike against the held session before the slice commits; the persisted restore token is the precedent; a Shell extension is the named last resort, not a mid-slice improvisation |
| **Bulk transfer starves or is starved** — a 100 MB stream through a 20 Mbps pacer takes ~40 s; done wrong it either bleeds the media classes or crawls | The priority ladder already answers it: bulk rides the tail, backpressure is a designed F-2 surface, and the J-G3 gate measures the audio bound DURING transfer — the R-G8 discipline extended, not renegotiated |
| **Hotel network blocks the catch-up** (D-0) — client isolation is real; every queued leg assumes reachability | Tailscale/hotspot fallback named in advance; worst case the catch-up waits for home Wi-Fi and wave 1's Mac-local work (F-2, D-4) proceeds — the ladder was ordered so pup-blocked days are never idle days |
| **F-2 design churn** — resumable transfer with backpressure is the wave's only genuinely novel protocol surface; ARQ-style vs fountain is a real fork | The ruling happens inside F-2 with the trade written down (the estimator-swap precedent); vectors freeze only at slice exit; no end-side code starts until they do (ruling 12 held the same line for the whole client) |
| **Consent UX scope creep** — file transfer invites settings sprawl | Owner decision 1 is made BEFORE F-3/F-4 start; the LYTE-PLAN §10 rule (capabilities on/off, no knob farms) applies to features too |
| **Solo-maintainer arithmetic** — the wave holds ~11 slices plus two joint gates | Every slice one worker-session at H2 calibration; the debt rungs are deliberately small and independently committable; F-6 is pre-declared droppable; J-G3a lands the headline feature early so a stretched wave still exits with clipboard proven |
