# Lyte Master Build Plan (2026-07-20)

*The plan of record. Synthesizes the three sibling build plans — core
(20260720-221101, LyteWire), host (20260720-221102), client (20260720-221103)
— under the Lyte-UDP decision (20260720-215100) and the protocol overview +
§6 addendum (20260720-193000). Where this doc and a sibling plan disagree,
this doc wins; the siblings are not edited. Every ruling in §4 was a real
inconsistency found at the interfaces, adjudicated here.*

## 0. Mission

One protocol, one host, one client per platform: aesthetically pure Swift on
both ends, C only at the hardware/OS boundaries, everything else ours to the
byte. Lyte-UDP is the only wire lyte-host will ever speak; the client's
GameStream stack is frozen scaffolding, deleted the moment it stops being
load-bearing; Sunshine is a bootstrap crutch, uninstalled at parity. The
product is a damage-driven remote desktop that ratchets a settled screen to
visually lossless, goes genuinely silent when nothing changes, and delivers
jitter-free intelligent audio as the constraint every other layer bends
around — then grows clipboard, drag-and-drop, and printing on the same
feature channels.

## 1. Vocabulary, numbering, gates, effort — one scheme

- **Slice IDs.** Core keeps `W0–W8` (plus the `W4a/W4b` split ruled in §4.5).
  Host slices keep their committed numbers, cited as **HS-3…HS-19** to avoid
  colliding with milestone names H1/H2. Client keeps **CL-1…CL-17**. The
  sibling docs' local numbering stays valid; this table is the master order.
- **Gate namespaces.** `W-` core, `R-`/`T-`/`Q-` pillars (unchanged), and two
  new **joint gates `J-G1` (H0b first pixels) and `J-G2` (H2 parity /
  Sunshine retirement)**, owned by this doc, spelled out in §3. No collisions.
- **Effort scale (host's, now universal).** S ≤ 2 days, M ≈ 3–7 days,
  L = multi-week. The client plan's finer scale (S ≈ session, M ≈ 1–2 days,
  L ≈ several days) is converted in the table below — most client letters
  read one notch smaller on the master scale.
- **Milestones.** H0a (finishing), H0b (first pixels), H1 (honest session),
  H2 (parity + retirement), H3+ (features), per the decision record §5.

## 3. The joint gates, spelled out once

**J-G1 — H0b first pixels.** Owned jointly; this text is canonical. The Lyte
client in `lyte-cli` debug mode (manual host:port, statics pinned
out-of-band, no pairing), on the wired/Wi-Fi LAN, renders the host's live
desktop over pure Lyte-UDP: **Noise IK completes** (or the recorded
`--insecure` fallback, §4.1, with a mandatory re-run when W5 lands); video
shards arrive as chan=2 datagrams under the 24 B envelope + 1112 B plaintext
budget (§4.2); per-frame RS FEC recovers 1% induced netem loss with zero
visible artifacts; DSCP 40 visible per packet in tcpdump; IDR-on-demand
heals a deliberately corrupted stream; glass-to-glass latency measured
(capture-ts→photon via the beacon's rough clock offset, cross-checked with a
phone-camera ms-clock photo); both ends' (chan, seq, frame) accounting logs
agree over a ≥5-minute soak. Host owns everything to the NIC; client owns
receive/reassembly/render and the latency measurement. Passes only
end-to-end.

**J-G2 — H2 parity and retirement.** The maintainer daily-drives lyte-host
for real work for one week (trigger declared at CP-2, §5). Then, as one
reviewed commit series plus one host action: the client demolition checklist
(client plan §6 — GameStream sources, `Vendor/enet`/CEnet, cert identity,
`_nvstream._tcp`, ClientStore migration, doc sweep; interior-format goldens
preserved and re-pointed) executes, and **Sunshine is uninstalled from the
host box in the same breath**. H2 does not exit until both are done. All R-gates
green; audio M7 envelope green; input-to-photon instrumented; HS-19 included
or explicitly slipped per CP-1.

## 4. Conflicts found & rulings

1. **H0b crypto posture** (host: real Noise day one; core: W5 grouped with
   the H1 slices, H0b needs only W0–W2; client: CL-1..4 never mention Noise).
   **Ruling: host wins.** Crypto retrofit re-tests every packetization
   decision and the AEAD tag changes the shard budget (next item); W5 moves
   onto the H0b critical path (it needs only W0 and runs parallel to W1/W2).
   Client CL-1 gains the Noise transport-open step. Fallback of record: if
   W5 stalls behind everything else, J-G1 may run once with `--insecure` on
   both ends — a schedule decision (CP-3), not a design change, and the gate
   re-runs with Noise on when W5 lands.
2. **Shard byte budget vs the 16 B Noise tag.** The overview's envelope row
   already accounts for the tag (24 B envelope + 16 B tag = 40 B overhead
   inside 1152), but the core plan's "payload ≤ 1128 B" (and W-G1's
   "enforcement exact at 1128 B") and the host's J-G1 draft ("1128 B payload
   budget") treat 1128 as plaintext. **Ruling: plaintext shard budget is
   1112 B**; the envelope rides as AAD; ciphertext+tag ≤ 1128; datagram
   ≤ 1152. W-G1 enforces 1112/1128. `--insecure` mode uses the same 1112 B
   shard budget so FEC geometry and gate results carry over unchanged.
3. **Video assembler ownership.** Client CL-2 planned its own
   `LyteVideoAssembler` (nanors decode + adapter feeding the *existing*
   depacketizer); core W2 owns `VideoAssembler` in Wire/ as a copy-adapt of
   the depacketizer emitting `DecodeUnit`. **Ruling: core wins.** CL-2
   shrinks to wiring core's `VideoAssembler` output into the existing
   `VideoSampleFactory`/display-layer path. The frozen depacketizer is never
   edited and serves as W-G3's oracle until deleted. Likewise CNanors: the
   client consumes RS only through core's `FecDecoder`; the root package
   drops its CNanors target per the core plan.
4. **Three versions of the H0b gate** (host §2 prose, client CL-4 row, core's
   "W-G1+W-G2+W-G3 required"). **Ruling: one canonical text, J-G1 in §3**,
   merging host's checklist with client's glass-to-glass measurement; core's
   requirement becomes W-G1+W-G2+W-G3+W-G6 (with the §4.1 fallback). This
   doc owns the gate text.
5. **Scheduling gap: CL-3 (H0b) needs codecs core never scheduled for H0b.**
   The chan=3 feedback-report codec was assigned to no W slice at all, and
   the beacon codec sat in W4 (H1). **Ruling: W4 splits** — **W4a** (beacon +
   feedback-report codecs, S, gate W-G5a, lands in wave 1) and **W4b**
   (session state machine, M, gate W-G5b, H1 as before).
6. **Beacon timing across plans.** Client CL-3 (H0b) echoes a beacon the
   host wouldn't send until HS-8 (H1), and host HS-8's residual-<1 ms gate
   needs `HostClockModel`, which the client scheduled at CL-10 in H2.
   **Ruling:** host emits the 1 Hz beacon from HS-7 (trivial once W4a
   lands) — which also makes CL-4's glass-to-glass clock offset honest — and
   **CL-10 moves from H2 to H1**, right after CL-7/CL-8, closing HS-8's gate.
7. **NACK honored at H0b.** Client CL-3's gate said "forced loss produces
   NACKs the host honors," but the host's NACK responder is HS-17 (H2), and
   core W2 explicitly leaves the NACK-decision output unconsumed until H2.
   **Ruling:** at H0b the heal path is IDR-on-demand; CL-3's gate is amended
   to IDR-request healing. NACK emission may land early but "host honors"
   is verified at HS-17.
8. **Demolition timing.** Client: triggered when daily-drivable, hard
   deadline H2; host: H2 exit gate includes deletion; decision record:
   deletion the moment it stops being load-bearing. **Ruling (all three
   survive):** the trigger is CP-2 (maintainer declares daily-drivable),
   execution is the client's one-commit-series checklist plus the Sunshine
   uninstall together, and J-G2 — the H2 exit — does not pass until both are
   done. Earlier than H2 is welcome; later is not.
9. **4:4:4 placement.** Decision record sketches 4:4:4 at H3+; host puts it
   in H2 (slice 19) because Sunshine already serves 4:4:4 on the host; client
   pulls decode-side work (CL-13) into late H2. **Ruling:** HS-19 stays in
   the H2 wave **behind maintainer checkpoint CP-1**; CL-13 stays (client-
   local, fixture-gated, no host dependency); the joint Q-gates run whenever
   both ends exist — with HS-19 if it makes H2, else at H3/H4.
10. **Numbering, gate names, and effort scales** were mutually inconsistent
    (host slices 3–19 vs CL-n vs W-n; client's S/M/L runs ~one notch finer
    than the host's; no name existed for the joint gates). **Ruling:** §1 —
    HS-/CL-/W- cross-references, J-G1/J-G2 joint gates, host's effort scale
    universal, client efforts converted in the master table.
11. **Overview §4 question 5 was never adjudicated.** The §6 addendum claims
    "§4's open questions are all answered" but lists only 1–4; question 5
    (1152 B as the universal shard budget) was left dangling. **Ruling:
    accepted.** 1152 B universal (1112 B plaintext per §4.2); the DPLPMTUD
    raise is an H3+ session-parameter item, not a v1 concern.
12. **Test vectors as deliverables.** Client gates (CL-1, CL-2) consume
    "core test vectors" and a "canned datagram corpus" that the core plan
    only implies via its fuzz gates. **Ruling:** every W slice ships
    versioned vector/corpus files as first-class artifacts (envelope vectors
    at W0, FEC matrices at W1, the packetized golden corpus at W2, beacon/
    feedback vectors at W4a) — they are the contract the client codes
    against before the host exists.

## 5. Maintainer checkpoints

- **CP-1 — 4:4:4 in H2, or slip.** At H2's back half, with R-gates green:
  does 4:2:0 parity suffice to retire Sunshine (HS-19 slips past J-G2
  unchanged), or is Work-mode 4:4:4 part of "parity" because Sunshine
  already serves it? Host plan's stated checkpoint; the call is made then,
  not now.
- **CP-2 — declare daily-drivable.** The demolition trigger. Deletion is the
  default, not a decision — this checkpoint only dates it. Starts the
  one-week daily-drive clock; J-G2 executes at its end.
- **CP-3 — `--insecure` J-G1 fallback.** Only if W5 lags the rest of the H0b
  ladder: run first-pixels insecure now and re-gate with Noise later, or
  hold the gate. Schedule call, maintainer's.
- **CP-4 — 10 ms audio packetDuration** (M7 item 6): decide from measurement
  during CL-11, as a negotiated capability.
- **CP-5 — pre-HS-13 portal spike verdict.** If the combined
  ScreenCast+RemoteDesktop session proves hostile (consent re-prompts, token
  invalidation), bless the uinput fallback as primary before slice 13
  commits, not after.
