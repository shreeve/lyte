# Lyte-UDP Shared Core (LyteWire) — Build Plan (2026-07-20)

*One of three build plans (core / host / client) implementing the Lyte-UDP
decision (20260720-215100) under the capstone rulings (20260720-193000 §2, §6
addendum). This plan owns the shared protocol package both ends import. It is
a plan, not code; nothing here edits the frozen GameStream stack.*

## TL;DR

**One new SwiftPM package, `Wire/` at the repo root, module name `LyteWire`**
— pure Swift, one vendored C leaf (nanors, moved here from the root package),
imported by both the root client package and `Host/` via path dependencies.
Everything in it is **sans-IO**: pure codecs and state machines that consume
bytes + an injected clock and emit bytes + actions. No sockets, no Foundation,
no threads — the host and client shells own I/O, which is what makes the ARQ
deterministically testable and keeps the WASM boundary clean by construction.
Build order: envelope + FEC + video interior first (unblocks H0b), ARQ + CTRL
next (unblocks H1), Noise/PAKE/capabilities after (completes H1), audio interior
for H2. The core ships to a sibling only through named gates (W-G1…W-G9 below).

## 1. Package location and module layout

Decision: a **third SwiftPM package**, not a target inside either existing one.
A target in the root package can't be imported by `Host/` without dragging the
macOS-only client tree along; a target in `Host/` inverts the dependency for
the client. Both packages take a `.package(path:)` dependency instead:

```
Wire/                          new package, repo root sibling of Host/
├── Package.swift              swift-tools-version 6.0; platforms macOS 15+, Linux
├── Sources/
│   ├── CNanors/               git mv from Vendor/nanors — product name unchanged,
│   │                          so the frozen client stack's `import CNanors` still
│   │                          resolves once the root package re-exports it
│   └── LyteWire/
│       ├── Envelope/          24B header codec, chan registry, TLV extension codec
│       ├── Fec/               fec-field codec, geometry table (resiliency §5.2),
│       │                      RS encode/decode wrapping CNanors
│       ├── Arq/               reliable sublayer: groups, ACK/NACK codecs, PTO timers
│       ├── Media/             video packetize/assemble (HEVC interior), Opus framing
│       ├── Crypto/            Noise IK, epochs/nonces, CPace PIN-PAKE (swift-crypto)
│       ├── Session/           four-state machine, capability CBOR, CTRL messages,
│       │                      clock-beacon codec, version negotiation
│       └── Types/             ChannelId, WireTimestamp (domain-tagged), RateBudget,
│                              PacerPolicy, DecodeUnit — the shared vocabulary
├── Sources/LyteWireTestKit/   SimNet (loss/reorder/dup/delay injector), VirtualClock,
│                              SplitMix64 seeded RNG — a product, so host/client test
│                              suites reuse the same harness
└── Tests/LyteWireTests/
```

Root `Package.swift` gains the path dependency and drops its own `CNanors`
target; `Host/Package.swift` adds `../Wire`. `HostCore` and `LyteKit` both
import `LyteWire`. The frozen GameStream files are not edited — they keep
importing `CNanors`, now supplied by the Wire package.

**Dependency ruling, made honestly.** `LyteWire` depends on **swift-crypto**
(`Crypto` module) on all platforms — no CryptoKit conditional import. On Apple
platforms swift-crypto is a thin shim over CryptoKit (zero added cost); on
Linux it vendors BoringSSL, which is the one sanctioned deviation from
"C only at OS boundaries": it is Apple-maintained, already in the root
package's dependency tree (pinned at 3.8+ for pairing today), and the
alternative — hand-rolling ChaCha20-Poly1305/X25519 — is exactly the crypto
we must not write. Confinement rule: `import Crypto` appears only under
`Crypto/`; the rest of the module sees a five-function internal surface
(DH, AEAD seal/open, hash, HKDF), so a future WASM build can substitute a
backend without touching protocol logic. **No Foundation anywhere in
`LyteWire`** — byte buffers are `[UInt8]`/`ArraySlice<UInt8>`; a CI grep for
`import Foundation` under `Wire/Sources/LyteWire` is part of every gate.

## 2. Scope: what the core owns (and pointedly does not)

Owns: every byte format and every pure decision procedure. Does not own:
sockets, cmsg/DSCP, timers-as-threads, the congestion estimator/control law,
the pacer scheduler, encoders/decoders, keystores. Formats for feedback and
NACK live here; the estimator that consumes them lives in the host plan.

**Exposed interfaces** (the contract the sibling plans reference):

- `Envelope` — 24B LE codec exactly per overview §2: `chan u8, flags u8,
  seq u16, frame u32, timestamp u64, fec u64`; payload ≤ 1128 B; TLV
  extension codec behind flags bit0. `ChannelId` registry: 0 CTRL (ARQ
  ordered), 1 audio, 2 video-active, 3 telemetry, 4 video-idle + final
  ratchet frame (ARQ one-shot groups), 8+ feature channels (ARQ ordered);
  5–7 reserved.
- `FecCodec` — fec-field pack/unpack (`shardIdx|dataShards|parityShards|
  scheme|reserved u32`); `FecEncoder/FecDecoder` over CNanors with the
  resiliency §5.2 adaptive geometry table. **Simplification of record:
  shards protect payload bytes only, never envelope bytes** — Sunshine's
  rebuilt-parity-header garbage-patch hack (see `RtpVideoQueue.swift`
  header comment) is deleted, not inherited.
- `ArqEndpoint` — sans-IO reliable sublayer. Three consumer shapes:
  long-lived ordered stream (CTRL, features) and one-shot message group
  (idle frame, final ratchet frame), each group retransmitting
  independently — no cross-group HOL, per decision record §8.1. API shape:
  `ingest(datagram, now) -> [Event]`, `send(message, group, now)`,
  `poll(now) -> (datagramsToSend, nextTimerDeadline)`. ACK format:
  cumulative + bitmap per (chan, group); NACK format: (chan, seq) lists
  with u16 serial arithmetic. Loss timers are RFC 9002-shaped PTO
  (RTT-adaptive, never fixed-interval — resiliency §1.3).
- `NoiseSession` — IK pattern, `Noise_IK_25519_ChaChaPoly_SHA256`,
  handshake message codecs (first datagram carries wire major version, per
  adjudication §8.3), transport-phase AEAD per channel, epoch rekey.
- `PairingPake` — CPace over X25519 (draft-irtf-cfrg-cpace), transcript
  bound to the Noise handshake hash (adjudication §8.2); emits the static
  keys to pin (storage is shell-side).
- `Capabilities` — minimal deterministic CBOR codec + intersect rules
  (unknown keys ignored); session-parameter renegotiation messages.
- `SessionStateMachine` — ACTIVE/IDLE/FROZEN/RECOVERY pure logic: inputs
  (feedback-silence 350 ms, feedback-returned, mode messages, pre-arm
  input, ratchet convergence), outputs (send-IDR-at-rate, mode CTRL
  message, freeze sends). The pre-arm flag persists through FROZEN
  (overview conflict 14).
- `Media` — `VideoPacketizer` (host) / `VideoAssembler` (client) sharing
  one layout; the assembler carries over the proven depacketizer interior:
  the Annex-B `Cursor` NAL walker, VPS/SPS/PPS split, AUD/SEI stripping,
  IDR-wait recovery discipline, emitting today's `DecodeUnit` shape.
  `AudioFramer`: Opus framing + 4+2 RS expressed in the fec field.
  Extraction method: **copy-adapt into `Wire/`, GameStream fields deleted**
  (no 8/24-byte Sunshine frame header, no `streamPacketIndex`, no RTP) —
  the frozen client files are never edited; golden outputs from existing
  `captures/` serve as reference oracles.
- `ClockBeacon` — 1 Hz clock-mapping message codec + echo (content per
  timing §2; the `HostClockModel` estimator itself is client-shell logic).
- Shared vocabulary structs: `RateBudget`, `PacerPolicy`, `WireTimestamp`
  (phantom-typed by clock domain: `HostMediaClock` vs `ClientClock`, so a
  domain mix is a compile error, not a sync bug).

**Design decisions pinned now** (the ones that bite later if left open):

1. **AEAD nonce = 64-bit extended per-channel counter, not the raw u16
   seq.** The u16 wraps in ~3.6 s at peak; the receiver reconstructs the
   extended counter SRTP-ROC-style from a wrap window. Epoch (rekey) is the
   nonce's high bits; both epoch keys stay valid for a grace window so
   in-flight packets survive a rekey.
2. **A retransmit is a byte-identical datagram resend** — same seq, same
   ciphertext. No new nonce is consumed, replay protection admits it once,
   and ACK ambiguity disappears because there is nothing distinguishable to
   be ambiguous about.
3. **Sans-IO is a rule, not a style.** Any function needing time takes
   `now: WireInstant`. This is what makes W-G4's exhaustive simulation
   possible and what keeps the WASM boundary from eroding.

## 3. Slice order and gates

| Slice | Contents | Gate | Size | Blocks |
|---|---|---|---|---|
| W0 | Package scaffold; envelope + TLV codecs; ChannelId; vocabulary types; CI on macOS + Linux; no-Foundation lint | W-G1 | S | everything |
| W1 | CNanors move; fec-field codec; FecEncoder/Decoder + geometry table | W-G2 | M | H0b host + client |
| W2 | Video interior: packetizer, per-frame FEC-group assembler, depacketizer copy-adapt; NACK-decision output (unconsumed until H2) | W-G3 | L | **H0b** |
| W3 | ARQ endpoint, ACK/NACK codecs, CTRL message framing; SimNet harness matures here | W-G4 | L | H1 host + client |
| W4 | Session state machine + clock-beacon codec | W-G5 | M | H1 |
| W5 | Noise IK, nonce/epoch scheme, rekey | W-G6 | L | H1 |
| W6 | CPace PIN-PAKE + pairing messages | W-G7 | M | H1 pairing |
| W7 | Capability CBOR + version negotiation + renegotiation messages | W-G8 | S | H1 |
| W8 | Audio interior: Opus framing + 4+2 RS | W-G9 | M | H2 audio |

Critical path to H0b: **W0 → W1 → W2** — nothing else gates first pixels
(H0b debug mode needs no ARQ: the host sends periodic IDRs; the client's
IDR-request can ride an unreliable CTRL message or wait for W3). W3–W7 gate
H1 and can start the moment W0 lands (W3 needs only the envelope). W4, W7,
W8 parallelize freely against W3/W5; W6 requires W5's handshake transcript.
Siblings can code against the §2 interface signatures from day one — the
structs are specified here precisely so host/client plans need not wait for
implementations to exist.

## 4. Testing strategy — the "we own ARQ correctness" answer

All of it runs with `DEVELOPER_DIR=/Applications/Xcode.app swift test` in
`Wire/` on the Mac and plain `swift test` on `pop`; both are CI legs. The
gate namespace is **W-** (R-/T-/Q- are taken, per overview §2).

- **W-G1 envelope**: round-trip fuzz (seeded, 10⁷ iterations) over random
  headers/TLVs including truncated and oversize inputs — decode never
  crashes, encode∘decode is identity, budget enforcement exact at 1128 B.
- **W-G2 FEC**: recovery matrices — for k ≤ 8, **every** loss pattern up to
  parity count recovers byte-exact and every pattern beyond parity count
  reports failure (never garbage); sampled random patterns for k up to 255;
  cross-checked against nanors reference behavior already soak-proven
  client-side (M3: 1,087 packets recovered).
- **W-G3 video interior**: golden corpus (Annex-B from `captures/` and the
  H0a file-output host) packetized → SimNet loss/reorder → assembled →
  byte-identical `DecodeUnit`s; integrity property: under any injected
  fault, the assembler emits correct bytes or nothing — never a corrupt
  unit. IDR-wait recovery discipline covered by scripted loss scenarios.
- **W-G4 ARQ** (the heart): (a) *exhaustive small-case model checking* —
  enumerate all delivery interleavings of ≤ 5 datagrams with ≤ 2
  losses/dups across 2 groups; assert exactly-once in-order delivery per
  group, independence across groups (a fully-lost group never delays a
  healthy one), and termination; (b) *seeded property simulation* — 10⁶
  randomized trials over loss ≤ 30%, reorder, dup, delay up to 5× RTT,
  including u16 seq-wrap crossings, with invariants checked every step and
  every failure reproducible from its seed; (c) *adversarial*: ACK
  forgery/replay shapes never induce livelock or unbounded retransmit.
- **W-G5 state machine**: transition-coverage table (every state × every
  input has an asserted outcome — including the illegal ones); properties:
  pre-arm survives FROZEN and is consumed exactly once by RECOVERY's IDR;
  RECOVERY enters at ≤ 50% stale estimate; two clean windows → ACTIVE.
- **W-G6 Noise**: `Noise_IK_25519_ChaChaPoly_SHA256` verified against
  published test vectors (snow/cacophony vector sets); self-handshake
  interop; malformed-handshake fuzz never panics and never leaks key
  material into transcripts; nonce/epoch unit tests prove no (key, nonce)
  pair ever repeats across rekey and seq wrap.
- **W-G7 PAKE**: CPace draft vectors; wrong-PIN aborts cleanly and yields
  no offline-testable material; transcript-binding negative test (tampered
  handshake hash fails).
- **W-G8 capabilities**: CBOR round-trip fuzz; unknown-key-ignored rule;
  intersect algebra (commutative, idempotent).
- **W-G9 audio framing**: 4+2 recovery matrix + framing round-trip against
  the client's existing audio path constants.

**Acceptance rule: no core slice is integrated into a host or client slice
until its W-gate is green on both platforms.** H0b integration specifically
requires W-G1 + W-G2 + W-G3. The netem-level gates (R-G1…G8) remain
host/client-plan territory — the core's gates are the layer below them.

## 5. Risk register

| Risk | Mitigation |
|---|---|
| ARQ subtleties: u16 wrap arithmetic, spurious PTO retransmits, ACK-of-retransmit ambiguity, cross-group interference | Byte-identical retransmits (§2.2); serial arithmetic helpers shared with the FEC/NACK paths and unit-tested at wrap; W-G4's exhaustive small-case enumeration is the design review |
| Noise implementation error (subtle, silent) | Vectors first (W-G6), pattern pinned to the WireGuard-proven IK, primitives from swift-crypto only, `Crypto/` confined and small enough for line-by-line external review before H1 ships |
| PAKE choice: CPace needs an Elligator2 map onto Curve25519 — pure-Swift GF(2²⁵⁵−19) field arithmetic we must write | Scope is one map function with draft vectors; X25519 itself stays swift-crypto's. Fallback of record: SPAKE2 needs group ops swift-crypto doesn't expose, so if CPace stalls the fallback is *scheduling* (PIN pairing slips a slice), not a different algorithm rushed in |
| Nonce reuse across rekey/wrap | Extended-counter scheme pinned in §2.1 with a dedicated W-G6 sub-test; rekey grace window bounded and tested |
| Clock-domain mixing (host-PipeWire µs vs client µs in one u64 field) | Phantom-typed `WireTimestamp` makes cross-domain arithmetic a compile error; beacon codec is the only sanctioned conversion point |
| WASM-boundary erosion (Foundation/socket creep; swift-crypto-on-WASI uncertainty) | No-Foundation CI lint from W0; sans-IO rule; crypto confined behind the internal five-function surface so a WebCrypto-backed substitute stays a leaf swap |
| Depacketizer copy-adapt drifts from proven behavior | Golden-corpus tests (W-G3) generated from the *frozen* path's outputs before adaptation begins; the frozen code is the oracle until deleted |
| Pre-handshake DoS (we own the flood surface, no RFC 9000 lineage) | Core provides a stateless HMAC retry-cookie codec for the first handshake datagram; the host shell decides when to demand it. Adversarial shapes are in W-G4/W-G6, not deferred |

## 6. What the sibling plans may assume

The host plan consumes: `Envelope`, `FecEncoder`, `VideoPacketizer`,
`AudioFramer`, `ArqEndpoint`, `NoiseSession`, `PairingPake`, `Capabilities`,
`SessionStateMachine`, `ClockBeacon`, `RateBudget`/`PacerPolicy` types, the
retry-cookie codec — wiring them to UDP sockets, cmsg DSCP 48/40, the pacer,
and the congestion estimator. The client plan consumes the mirror set
(`VideoAssembler` → `DecodeUnit` into the existing VideoToolbox path,
`HostClockModel` fed by `ClockBeacon`). Both get `LyteWireTestKit` for their
own simulation suites. Interface changes after a slice's gate is green are
edits to this doc first — same discipline the capstone imposed on §2 rows.
