# Lyte Host Build Plan — H0b through H3+ (2026-07-20)

*Host-side planning for the Lyte-UDP ladder (decision record 20260720-215100;
interface rulings in the protocol overview 20260720-193000 §2/§6). Covers
everything that runs on the host. The shared protocol package is `LyteWire`
(sibling plan 20260720-221101-build-plan-core.md — slices W0–W8, gates
W-G1…W-G9); this plan consumes its interfaces and never rebuilds them.
Client work is the other sibling's; joint gates are stated as joint.*

## 0. Where the host actually is

Committed (slices 1–2, `4619121`/`f529c57`): headless portal ScreenCast v5
(restore-token, pinned-by-serial) and Mutter fallback → `CPipeWireCapture`
(C leaf, SPA pods, tick timer on the loop thread) → `CHevcEncode` (libavcodec
`hevc_nvenc`, Sunshine low-latency recipe: CBR, single-frame VBV, infinite
GOP, zero B-frames, P1/ULL, one in flight) → Annex-B file, with a 60 fps
idle-floor re-encoding the retained last frame. `HostCore` verifies
stream-startability (VPS/SPS/PPS+IRAP). Everything downstream of the encode
callback — wire, session, input, audio — does not exist. Sunshine still runs
on the host box and must not be disturbed until the H2 exit gate.

Doctrine carried forward: C only at hardware/OS leaves (system libs, never
vendored mid-pipeline engines); pure-Swift logic lives in targets that build
and unit-test on macOS; every slice is a committable unit with a measured
acceptance gate; dev loop is rsync → build on the host over ssh (BatchMode).

**Sequencing notes.**

- Slice 3 first: it is already approved, it exercises the encoder-reconfig
  path (QP stepping) that slice 19 productionizes, and its all-skip detector
  is the convergence signal slice 11's mode machine consumes. Cheap now,
  load-bearing twice later.
- Slices 4 and 6 have no core dependency beyond W0's types and can start
  immediately; slice 5 is the first true integration point (needs W0–W2
  green, per §3).
- H0b keeps the 60 fps idle-floor and ACTIVE-only operation. Honest-but-thin
  session for H0b = **real Noise IK (`NoiseSession`, W5) with statics pinned
  out-of-band** (printed/copied key file), no PAKE, no discovery, no ARQ.
  Reasoning: the 16 B AEAD tag changes the shard byte budget and encrypting
  after the fact re-tests every packetization decision — crypto retrofit is
  the classic trap. PAKE/discovery genuinely add nothing to "first pixels."
  A `--insecure` flag may exist during the slice for bring-up but the slice
  gate runs with Noise on (overview N2 precedent). This is one deliberate
  amendment to the core plan's minimal H0b (which requires only W0–W2):
  if W5 lags badly, the fallback of record is shipping the joint gate
  `--insecure` and re-running it when W5 lands — a schedule decision, not a
  design change. IDR-on-demand in H0b is an idempotent unreliable CTRL
  datagram (client fires it repeatedly until healed); it migrates to
  `ArqEndpoint` in slice 8.
- Slice 11 is the largest H1 item because it retires the idle floor: the
  tick machinery becomes the ratchet scheduler (image-quality doc's framing),
  and IDLE means genuine silence plus reliable sparse frames. The four-state
  machine (ACTIVE/IDLE wire modes + FROZEN/RECOVERY overlay) is built here
  with FROZEN/RECOVERY stubbed until slice 18.
- Slice 19 placement: the decision record sketches 4:4:4/ratchet at H3+,
  but "parity" on this plan includes the Work-mode switch because Sunshine
  (master) already serves 4:4:4 on the host and the ratchet is the product's
  headline. If the maintainer judges 4:2:0 parity sufficient to retire
  Sunshine, slice 19 slips past the H2 exit unchanged — explicit checkpoint,
  maintainer's call at the time.
- Priority order everywhere: CTRL/input > audio > fresh video > video
  tail+NACK > ratchet > telemetry. The pacer implements it from slice 6 with
  empty classes; classes populate as slices land.

## 2. The joint H0b gate (stated once, owned jointly)

The unmodified Lyte client in Lyte-UDP debug mode (manual host:port, pinned
statics, no pairing), on the wired/Wi-Fi LAN, **renders the host's live desktop
over pure Lyte-UDP**: Noise IK completes, video shards arrive as `chan=2`
datagrams under the 24 B envelope + 1128 B payload budget, per-frame RS FEC
recovers a 1% induced netem loss with zero visible artifacts, DSCP 40 is
visible per packet in tcpdump, IDR-on-demand heals a deliberately corrupted
stream, and both ends' (chan, seq, frame) accounting logs agree over a
5-minute soak. Host owns everything up to the NIC; client sibling owns
receive/reassembly/render; the gate passes only end-to-end.

## 3. LyteWire dependency map

Core slice names per the core plan (20260720-221101, §3); the acceptance rule
there holds — no host slice integrates a core deliverable before its W-gate
is green on both platforms.

slice 3 runs first and feeds it ratchet-shaped streams too.

## 4. Module tree evolution (`Host/Sources`)

```
HostCore/            grows: Pacer (token bucket + priority classes), shard
                     queues, RatchetController, congestion Estimator +
                     control law (emits RateBudget/PacerPolicy), NackResponder,
                     send-timestamp rings, Histogram — pure Swift,
                     deterministic, unit-tested on macOS with SimNet
LyteWire (dep)       ../Wire path dependency (core plan §1); HostCore imports it
lyte-host/           orchestration: portal/Mutter session, main loop,
                     Avahi leaf (over existing DBus.swift), RemoteDesktop
                     portal calls, doctor/telemetry surface
CPipeWireCapture/    exists — gains capture-pts export (µs) for envelope ts
CHevcEncode/         exists — gains dynamic reconfig (bitrate/CQ), 4:4:4
                     yuv444p path + full-range BT.709 VUI, swscale conversion
CNetIO/         new  C leaf: sendmmsg/recvmmsg, CMSG TOS per packet,
                     SO_TIMESTAMPING (CMSG macros are unreachable from Swift)
CPipeWireAudio/ new  C leaf: monitor-source stream, 5 ms quantum, graph-clock ts
COpusEncode/    new  C leaf: libopus (system lib), CELT restricted-lowdelay
CInputUinput/   new  C leaf (H2, fallback only): uinput ioctl surface
CCudaConvert/   only if measured: RGB→YUV444 kernels (Sunshine PR #4965 ref)
```

All new C targets are hardware/OS leaves over system libraries — consistent
with doctrine, but the honest count grows from 4 boundaries to 7–8; each new
leaf needs the same header-contract + error-buffer discipline as the two
existing ones. `HostCore` is where the protocol logic lives precisely so the
leaves stay dumb.

## 5. Cross-cutting

**Netem rig (gates R-G1…G8).** Scripts in `Scripts/netem/`, one per gate row,
run *on the host* via ssh: egress `tc qdisc … netem` on the LAN interface with a
u32 filter matched to the client IP (video/audio direction), plus `ifb`
redirect when a gate needs impairment toward the host (feedback loss for
G6/G7). Each script prints the exact profile and duration; gates measure at
the client (existing kernel-timestamp probes) except G8, which is host-side:
tcpdump/SO_TIMESTAMPING at the host's NIC. A loopback variant (netem on `lo`,
local test receiver) serves pacer/FEC development before the client is ready.
Sunshine coexistence: filters scoped to lyte-host's port so the crutch is
never impaired.

**Telemetry.** `HostCore.Histogram` (p50/p95/p99 + counters), populated per
timing §8: capture→encode-start, encode duration, pacer queue delay per
class, frame wire-drain, audio inter-send at NIC, input receive→inject,
beacon publish age. Surface: periodic log line + full dump on exit from
slice 6; a local stats socket (JSON) when the doctor grows a host page.
Instrumentation lands with the slice that creates each edge, never later.

**`lyte sniff`.** Envelope headers are AD, not ciphertext, so a header-level
dissector (chan/seq/frame/ts/fec, pcap or live) is buildable the week
slice 5 lands — build it then; it is the debugging story Wireshark can't
give us. Payload decryption behind a debug key-export flag comes with H1.

## 6. H3+ sketch (less depth, honest options)

- **Clipboard.** Primary: the **portal Clipboard API attached to the
  RemoteDesktop session** (available in RemoteDesktop v2 era portals; GNOME
  implements it) — we already hold that session for input, and it gives
  selection-change signals + fd-based transfer both directions.
  `wl-clipboard` is *not* a real fallback on GNOME (no wlr-data-control;
  its hidden-surface trick is focus-dependent) — investigate the portal path
  first and treat a GNOME Shell extension as the last resort. Rides an
  `ArqEndpoint` feature channel (chan ≥ 8); MIME negotiation TLV per the
  transport pillar.
- **Printing (H5).** Sketch: a virtual IPP-Everywhere printer on the host
  (CUPS `everywhere` queue or a small ippserver leaf) accepting PDF jobs and
  forwarding them over a feature channel; client submits to the macOS print
  system. No CUPS driver authoring; PDF is the pivot format.
- **File transfer** reuses the same feature-channel shape; fountain-code
  re-evaluation (resiliency §1.1) belongs here, not in media.

## 7. Risk register

| Risk | Mitigation |
|---|---|
| **Portal RemoteDesktop quirks** (H2 input): combined ScreenCast+RemoteDesktop session may re-prompt consent or invalidate the existing restore token; keycode vs keysym mapping; locked session inhibits both (named error exists) | Prototype the combined session in a spike *before* slice 13 commits to it; persist the combined token; send evdev keycodes and let the host session's XKB map own layout; uinput fallback leaf is the escape hatch (udev rule documented); locked-session = named doctor diagnosis, stated limitation |
| **PipeWire audio capture**: monitor-source discovery, 5 ms quantum not honored (graph may run 10–20 ms), clock domain mismatches | Force `node.latency = 240/48000` on our stream; buffer-slice to exact 5 ms Opus frames host-side regardless of delivered quantum; timestamps always from graph clock, never wall clock |
| **NVENC 4:4:4 via libavcodec**: Rext profile + yuv444p + full-range VUI plumbing through `hevc_nvenc` on Ubuntu 26.04's ffmpeg; CQ/dynamic-reconfig limits (bitrate reconfig is supported; per-pass QP stepping may not be) | Empirical probe at startup (Sunshine discipline) — a real 4:4:4 test encode gates the capability advertisement; ratchet fallback is `constqp` + reconfigure per pass; last resort is the raw-SDK question the image-quality doc already scoped (only if LTR also demands it) |
| **RGB→YUV444 conversion cost** at 2048×1280@60 on CPU | swscale first, measure; CUDA kernels (`CCudaConvert`, Sunshine PR #4965 GPL reference) only on measured need — don't pay for two conversions before measuring one |
| **Avahi**: assumed present/running on GNOME hosts; D-Bus API quirks | It ships default on Ubuntu GNOME; probe at startup, degrade to manual host:port with a doctor line; embedded mDNS responder is the H6 single-binary item, not now |
| **Noise/ARQ correctness is ours** (no RFC 9000 lineage): pre-handshake floods, retransmit edge cases | LyteWire owns the logic (W-G4/W-G6 adversarial tests) but the host owns the exposed socket: rate-limit unauthenticated first datagrams, demand the core's retry cookie under load, no allocation before handshake progress |
| **Sunshine coexistence until H2 exit**: port collisions, NVENC session count, portal sessions | Distinct UDP port; RTX 4050 allows 8 concurrent NVENC sessions (two hosts fine); portal supports concurrent ScreenCast sessions; netem filters scoped (§5) |
| **Estimator tuning burns time** (burst-dispersion on Wi-Fi aggregation is noisy) | Weight down <8-packet trains as designed; gate G3 ("jitter must not downshift") is the overfit tripwire; ship slice 16 with conservative constants and let G5 tune them |
| **Solo-maintainer scope**: H2 is six slices, three of them L | The ladder is strictly serial and each slice is independently committable; the Sunshine crutch removes schedule pressure — nothing breaks if H2 takes longer |

## 8. Critical path, called

H0b critical path: **LyteWire W0→W1→W2 → host slice 5 (video channel wiring)
→ slice 7 (Noise, W5) → joint gate with the client's receive path.**
Host-only work (slices 3, 4, 6) fills any core-package wait. The single biggest risk
on the whole plan is **portal RemoteDesktop input injection** — it is the
one H2 component with no in-repo precedent, a consent/token surface that has
burned us before, and a hard dependency for "Sunshine retires"; hence the
pre-slice-13 spike and the uinput fallback planned as real work, not a
footnote. Second-biggest: NVENC ratchet reconfig through libavcodec
(slice 19), already fenced with the `constqp` fallback.
